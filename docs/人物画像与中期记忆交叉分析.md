# 人物画像与中期记忆交叉分析

> 分析对象：MaiBot（`references/MaiBot/`）、mem0（`references/mem0/`）、Zep / Graphiti（`references/zep/`）。
> 目标：为 LinYi 设计"记得对方是谁、记得近期聊过什么"的拟人化记忆层，使其更像一个长期生活在电脑中、拥有稳定人格与社交关系的虚拟生命。

---

## 1. 问题空间

LinYi 当前已有：

- `ReaderProfile`：读者的基础画像（姓名、关系阶段、偏好语气、已知事实）。
- `OCCharacterSheet` / `CharacterCardModule`：OC 角色卡与世界书。
- `MemoryStream`：自然语言记忆流，支持 recency/importance/relevance 三因子检索。
- `ConversationQueue`：近期对话队列。
- `PromptSurface`：将上下文组装成 prompt。

但仍缺少：

1. **人物画像的动态注入**：当读者或 OC 被提及时，prompt 中不会自动出现对方的画像，导致林逸"失忆式回复"。
2. **中期记忆压缩**：对话历史只会被原样保留或简单检索，没有 MaiBot 式的"聊天回想"（mid-term memory）压缩机制。
3. **结构化事实提取**：`ReaderProfile.known_facts` 是静态的，没有随对话自动提取、去重、修正的能力。
4. **多实体印象管理**：对读者、多个 OC 的印象是分散的，没有统一的"当前会话涉及谁、每人印象如何"的视图。

---

## 2. 参考项目分析

### 2.1 MaiBot：群聊拟人化 Bot 的人物画像与中期记忆

MaiBot 在 `src/maisaka/memory/person_profile.py` 中实现了 **Maisaka 人物画像自动注入服务**，核心设计：

- **候选收集**：从当前 anchor message 及其上下文中识别可能相关的人物：
  - 当前消息发送者（`sender_candidate`）
  - 被 @ 的目标（`at_candidate`）
  - 被回复消息的发送者（`reply_candidate`）
- **去重与优先级**：按"当前对象优先"顺序收集，限制最大画像数（默认 3），避免 prompt 膨胀。
- **画像文本**：通过 `memory_service` 查询人物的 `profile_text`，截断到 900 字符后注入 planner。
- **中期记忆（`src/maisaka/memory/mid_term.py`）**：
  - 当聊天上下文被裁切时，将被移除的消息通过 LLM 压缩成 `MidTermMemorySummaryModel`（summary + recall_cues）。
  - 保存为一条特殊的 ComplexSessionMessage，带有时间范围、参与人物、召回线索。
  - 支持基于 recall cues 的向量召回。

**可借鉴点**：
- "当前会话涉及人物"的识别与画像注入，让 Bot 在群聊中像记得每个人一样回复。
- 聊天记录的 LLM 压缩摘要，平衡上下文长度与记忆完整性。
- 画像候选的优先级排序与截断，防止 prompt 过度膨胀。

### 2.2 mem0：通用 LLM 长期记忆层

mem0 的核心在 `mem0/memory/main.py`，提供 `Memory` 类：

- **add(messages, user_id, ...)**: 接收消息列表，使用 LLM 提取记忆事实，存入向量数据库。
- **search(query, user_id, ...)**: 基于 query embedding + BM25 + 实体 boost + 时间衰减进行检索。
- **get_all / update / delete / history**: 完整的记忆 CRUD 与版本历史。
- **实体作用域**：通过 `user_id`, `agent_id`, `run_id` 对记忆进行多租户隔离。
- **事实提取 prompt**：`ADDITIVE_EXTRACTION_PROMPT` 等新事实与现有事实对比，避免重复。

**可借鉴点**：
- 用 LLM 从对话中自动提取事实，替代手工维护 `known_facts`。
- 向量 + 关键词 + 实体 + 时间的混合检索，比纯向量更准确。
- 记忆的版本历史，支持"人/事是会变的"这一拟人化设定。

### 2.3 Zep / Graphiti：时序知识图谱

Zep 商业版的核心是 **temporal knowledge graph**，开源实现为 Graphiti。其关键理念：

- 将对话中的实体和关系构建为**时序图**。
- 关系会随时间演化（`valid_from`, `valid_to`），支持"之前是朋友，后来决裂"。
- 检索时同时考虑语义相似度和时序相关性。

**可借鉴点**：
- 人物关系不是静态权重，而是带时间戳的边。
- 适合长期运行后回答"林逸和读者的关系如何变化""OC 之间的信任何时破裂"等问题。
- LinYi 已有 `RelationshipGraph`，可引入时序边（timestamp + evidence）和关系版本化。

## 3. 交叉对比

| 维度 | MaiBot | mem0 | Zep/Graphiti | LinYi 现状 |
|---|---|---|---|---|
| 人物画像注入 | ✅ 自动识别会话中人物并注入 | ❌ 不直接提供画像注入 | ❌ 不直接提供 | ⚠️ ReaderProfile 静态，未自动注入 |
| 事实提取 | ⚠️ 依赖 memory_service 内部 | ✅ LLM 提取 + 去重 | ✅ 图谱事实抽取 | ❌ 无自动事实提取 |
| 中期记忆压缩 | ✅ Mid-term memory 摘要 | ❌ 不压缩，保存原始消息 | ⚠️ 图谱边即压缩 | ❌ 仅保留原始对话 |
| 关系时序演化 | ❌ 静态画像 | ⚠️ 支持 history | ✅ 时序边 | ⚠️ RelationshipGraph 有证据/时间戳但无版本化 |
| 检索方式 | 关键词/向量召回线索 | 向量+BM25+实体+时间 | 图遍历+语义 | recency+importance+relevance |
| 工程复杂度 | 中 | 中 | 高 | 低（现有模块已解耦） |

## 4. LinYi 补强方案

基于以上分析，决定分三步补强：

### 4.1 人物画像自动注入（PersonaInjector）

参考 MaiBot 的 `person_profile_injector` 和 mem0 的 entity scoping：

- 新增 `PersonaInjector` 模块，订阅 `event.reader.interaction`, `data.reader.message`, `data.oc.town.event`, `data.conversation.queue.update`。
- 从消息中提取涉及的人物（读者、OC）。
- 查询 `ReaderProfile` 和 `OCCharacterSystem` / `CharacterCardModule`，生成画像文本。
- 发布 `data.persona.injected` 事件，包含 `reader_profiles` 和 `oc_profiles`。
- `PromptSurface` 订阅该事件，更新 `reader_context` / `character_definition` 槽位。

效果：林逸在回复时会像记得"对方是谁"一样，自动在 prompt 中带上相关画像。

### 4.2 ReaderProfile 增强：persona_summary 印象摘要

参考 MaiBot 的 `profile_text`：

- 在 `ReaderProfileData` 中新增 `persona_summary: str`。
- 提供 `update_persona_summary(summary: str)` API，可由 LLM 定期根据近期互动生成。
- `PersonaInjector` 优先使用该摘要，回退到 known_facts / relationship_stage。

### 4.3 中期记忆压缩（MidTermMemory / ChatRecall）

参考 MaiBot 的 `mid_term.py`：

- 当 `ConversationQueue` 超过容量或被显式触发时，将溢出部分通过 LLM 压缩为摘要。
- 摘要保存到 `MemoryStream` 作为 `reflection` 或 `conversation_summary` 类型。
- 保留 recall_cues，支持后续向量/关键词召回。

效果：长期运行后，远期对话不会以原始消息塞满 prompt，而是以压缩摘要形式存在。

### 4.4 关系图谱时序化（可选增强）

参考 Zep/Graphiti：

- 在 `RelationshipGraph` 中支持关系的有效时间窗口（`valid_from`, `valid_to`）。
- 新增关系版本历史，支持"关系演变"查询。
- 将高重要性社交事件自动转为时序边证据。

---

## 5. 实施顺序

1. ✅ **PersonaInjector + ReaderProfile.persona_summary**：已接入 PromptSurface，让回复更有人情味。
2. ✅ **ConversationQueue 中期记忆压缩**：已通过 `data.conversation.queue.evicted` + `MidTermMemory` 实现，摘要存入 `MemoryStream`。
3. ✅ **LLM 事实提取器**：已实现 `LLMFactExtractor`，自动从对话/OC 社交事件提取稳定事实，写入 `ReaderProfile.known_facts` 与 `OCCharacterSheet.known_facts`，并受 `immutable_facts` 保护。
4. ⬜ **RelationshipGraph 时序化**：长期演进，增强"关系变化"叙事能力。

---

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| 画像注入导致 prompt 过长 | PersonaInjector 限制每轮最大画像数；PromptSurface 已有截断。 |
| 事实提取幻觉 | 使用保守 prompt，仅提取高置信度事实；提供人工审核接口。 |
| 中期摘要丢失细节 | 保留原始消息到 MemoryStream，摘要仅用于 prompt 注入。 |
| 关系版本过多 | 设置版本数量上限，定期合并相似关系。 |
