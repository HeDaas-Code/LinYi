# Mem0 技术笔记

## 项目概述

Mem0 是一个面向 AI Agent 与助手的智能记忆层，核心目标是把对话中的关键事实提取出来、分层持久化，并在需要时高效检索。它介于应用与模型之间：对话结束后调用 `add` 提取结构化记忆，模型调用前通过 `search` 召回相关上下文。2026 年 4 月发布的新算法强调「单次 ADD-only 提取」（只新增、不覆盖）、实体链接、多信号检索（语义 + 关键词 + 实体 + 时间）以及时间推理，在 LoCoMo、LongMemEval 等长程记忆基准上表现突出。对 LinYi 而言，Mem0 提供了一个可直接复用的「读者-OC-世界」长期记忆范式：读者偏好不会随着新会话丢失，OC 对读者的态度能持续演化，剧情中的重要决策也能被时间感性地召回。

## 核心架构 / 关键模块

- **Memory 主类**：提供 `add / search / get / update / delete / history` 等统一接口，同时支持开源 SDK（`Memory`）与托管平台（`MemoryClient`）。
- **多层记忆模型**：Conversation（单轮）、Session（`run_id` 级）、User（`user_id` 级）、Org（跨用户共享），分别对应不同生命周期。
- **提取流水线**：上下文查找 → LLM 事实提取 → 去重 → Embedding → 实体链接，新事实以追加方式写入，避免静默覆盖旧记忆。
- **多信号检索**：语义向量相似度、BM25 关键词、实体关联、时间意图四种信号并行打分并融合排序。
- **异构存储后端**：SQL 库存事实与元数据、向量库存 Embedding、可选图数据库存实体关系。
- **Provider 插件体系**：LLM、Embedding、向量存储、图存储、Reranker 均可替换，方便接入不同模型与基础设施，LinYi 可根据成本与效果灵活切换后端。

## 与 LinYi 最相关的概念

- **读者级长期个性化**：通过 `user_id` 记住每位读者的偏好、过往剧情选择、对 OC 的态度，实现跨会话的「量身定制」。
- **事实化记忆替代原始聊天记录**：不重复塞入完整对话，而是存储「读者喜欢虐主情节」「OC A 曾背叛 OC B」等可复用事实。
- **时间推理**：能回答「最近发生了什么」「上周我们讨论到哪了」「当前计划是否过期」等带有时态的问题。
- **实体链接**：把读者、OC、地点、事件、偏好等关联起来，检索时可按实体 boosting。
- **作用域隔离**：`user_id / agent_id / run_id / metadata` 组合防止不同读者、不同 OC、不同故事线的记忆串味。
- **记忆过期与遗忘**：支持 `expiration_date`，让临时计划、短期目标在过期后自然淡出，模拟选择性遗忘。

## 对 LinYi 的具体建议

- 采用 ADD-only 提取策略保存读者偏好、剧情决策、OC 关系变化等事实，避免旧设定被新对话覆盖。
- 用 `user_id` 标识读者、`agent_id` 标识 OC、`run_id` 标识单次创作会话，让记忆隔离清晰。
- 实现「语义 + 关键词 + 实体 + 近因」的混合检索，优先召回与当前话题和角色相关的记忆。
- 为记忆附加 `category / story_arc / world_state` 等元数据，便于按剧情线过滤。
- 对临时性目标使用 `expiration_date`，让会话级计划在过期后自动淡出检索。
- 在记忆写入时做轻量实体抽取，建立读者-OC、OC-OC、事件-地点之间的关联边。
- 将记忆读写封装为内部 MCP 工具，让创作 Agent 与 OC Agent 都能像调用能力一样主动存取记忆。
- 在记忆搜索后加入轻量重排序（Reranker），把与当前角色或剧情线最相关的记忆排在前面。
