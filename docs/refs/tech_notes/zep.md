# Zep 技术笔记

## 项目概述

Zep Cloud 是面向 Agent 的托管记忆平台，其核心能力由时序知识图框架 Graphiti 驱动。与单纯向量检索不同，Zep 强调把对话中的实体、关系、偏好、事件抽取成一张可演化的知识图，并随时间推移更新。该仓库主要存放示例代码、框架集成与基准测试，而产品服务本身是闭源托管。Zep 的默认本体（Ontology）定义了 User、Assistant、Preference、Location、Event、Object、Topic、Organization、Document 等节点类型，以及 LOCATED_AT、OCCURRED_AT 等边类型，便于结构化地理解和检索记忆。LinYi 可借鉴其「图优先」思路：把 OC、读者、地点、剧情事件都变成图中的节点，用边表达关系与历史，从而支持更复杂的社交推理与剧情回溯。例如，当 OC A 对读者说出一句关心的话时，这句话不仅应作为文本记忆保存，还应在图中新增或加固一条「OC A —关心—> 读者」的边，并在后续互动中被用于语气与策略调整。

## 核心架构 / 关键模块

- **时序知识图（Graphiti）**：将实体、关系和事件以带时间戳的图结构存储，支持随对话演化和回溯历史状态。
- **本体驱动抽取**：通过预定义 Schema（如 User、Preference、Event）指导 LLM 做实体与关系识别，Preference 类型被设置为高优先级。
- **偏好与身份持久化**：自动捕捉用户偏好、选择、厌恶，并与用户节点长期绑定。
- **多框架集成**：提供 LangGraph、CrewAI、AutoGen、Pydantic AI、Vercel AI SDK 等集成示例。
- **评估体系**：内置 LoCoMo、LongMemEval 等长程记忆评测与 `zep-eval-harness` 评测框架，方便量化记忆召回质量。
- **会话与实体解析**：同一用户在不同会话中被识别为同一节点，指代消解（如 "He"）依赖历史上下文补全。

## 与 LinYi 最相关的概念

- **本体化角色与世界建模**：把读者、OC、地点、事件、物品、偏好都定义为图节点，比纯文本记忆更利于推理。
- **偏好低阈值捕获**：Zep 对 "I want / I like / I prefer" 等表达使用低敏感度阈值，确保个性化信息不被遗漏。
- **关系图演化**：OC 之间的好感、信任、冲突可以建模为带权重的边，并随事件更新。
- **时间与位置绑定**：事件边带时间戳，地点边描述「谁在哪」，便于回答「上周 OC A 在做什么」。
- **跨 Agent 共享记忆**：同一用户或同一世界下的多个 Agent 可共享知识图，避免重复学习。
- **时序版本控制**：关系与事件可随时间更新，保留历史快照，支持「那时他还不知道真相」之类的叙事查询。

## 对 LinYi 的具体建议

- 为 LinYi 定义轻量本体：Reader、OC、Location、Event、Preference、Topic、StoryArc、Document（作品）。
- 将 OC 关系显性化：使用 `friend_of`、`distrusts`、`owes_favor`、`loves` 等语义边，并在事件后按规则更新权重。
- 对读者表达进行低阈值偏好抽取，写入 Preference 节点，在后续创作中优先反刍。
- 把重要剧情事件作为 Event 节点，绑定时间戳与参与实体，支持「回顾过往」类查询。
- 利用图遍历实现「谁和谁是朋友」「OC A 知道哪些读者秘密」等社交推理。
- 参考 Zep 的集成思路，把 LinYi 的记忆接口做成可插拔组件，方便接入不同 Agent 框架。
- 定期运行图一致性检查，删除过期或矛盾的边，并用新事件版本化旧关系，避免关系图僵化。
