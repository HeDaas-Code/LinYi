# BabyAGI 技术笔记

## 项目概述

BabyAGI 最初是 Yohei Nakajima 于 2023 年 3 月提出的自主任务规划原型，当前仓库已演变为一个实验性的「自构建」Agent 框架。其核心是 Functionz：一个把 Python 函数注册、版本化、存储到数据库，并自动解析依赖、注入密钥、触发执行的运行时。开发者可以通过装饰器注册函数，函数之间声明依赖关系，框架自动按需加载；更有 `code_writing_functions` 与 `self_build` 等草稿包，尝试让 Agent 根据任务描述自动生成新函数并入库，实现能力自我扩展。对 LinYi 而言，BabyAGI 的启发不在于直接复用其代码，而在于把「能力」视为可版本、可依赖、可自扩展的函数资产，让系统随着与读者的互动逐步进化出更适合当前用户的创作策略。

## 核心架构 / 关键模块

- **Functionz 框架**：`FunctionRegistrar` 负责函数注册与版本管理，`FunctionExecutor` 负责依赖解析与执行，`DBRouter` 提供持久化存储。
- **函数元数据**：支持 `imports / dependencies / triggers / key_dependencies / metadata` 等字段，描述函数的依赖与触发条件。
- **自动依赖解析**：执行时递归加载依赖函数与外部库，缺少的 Python 包会自动尝试 pip 安装。
- **触发器机制**：某个函数执行后可触发其他函数，例如函数新增/更新后自动生成描述与 Embedding。
- **自构建包**：`process_user_input` 将用户需求拆解为可复用函数，`self_build` 批量生成任务并驱动函数创建。
- **Web Dashboard**：Flask 可视化界面，用于管理函数、查看依赖图、监控执行日志与密钥。

## 与 LinYi 最相关的概念

- **技能即函数**：把 LinYi 的创作、反思、记忆整理等能力抽象为可注册、可版本化的函数，形成技能库。
- **依赖图管理**：明确能力之间的依赖关系，便于组合和复用，例如「反思」依赖「读取记忆」与「重要性评分」。
- **自扩展能力**：通过 LLM 生成新函数或提示词模板，让 LinYi 在运行中逐步习得新的创作技巧。
- **触发式自动化**：利用触发器在特定事件后自动执行记忆归档、反思、关系更新等后台任务。
- **执行日志与可观测性**：完整记录函数调用、输入输出、耗时、错误，便于调试和审计，也支持通过日志复盘 LinYi 的决策路径与进化轨迹。

## 对 LinYi 的具体建议

- 建立 LinYi 的 Skill Registry，把提示词工程、情节生成、角色反思、记忆压缩等都注册为带版本和依赖的函数。
- 为每个技能声明 `dependencies` 与 `imports`，让执行器自动解析前置能力，避免硬编码调用链。
- 设计触发器规则：例如「重要事件写入记忆」后自动触发「反思摘要」或「关系更新」。
- 在受控沙箱中实验自构建能力，让 LLM 根据读者反馈生成新的提示词片段或短篇技能函数。
- 提供可视化 Dashboard 查看技能依赖图与执行日志，帮助开发者理解 LinYi 的「大脑」如何运转。
- 对生成的代码保持人工审核与版本冻结机制，防止自我扩展污染核心身份或世界观。
